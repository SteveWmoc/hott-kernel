# Theorem Finder Experiment v0

## Purpose

Test whether an automated system can discover bounded, formally verified lemmas
whose presence measurably improves later proof search.

The experiment separates three questions:

1. Which propositions should be considered?
2. Which library material is likely to help verify them?
3. Does a proposed proof pass the ordinary `hott-kernel` checker?

Only the third question participates in logical trust.

## Initial algebraic language

The first search space is intentionally small.

- One base type `A`.
- Constants `0, 1 : A`.
- Binary operations `+ , * : A -> A -> A`.
- Equality as the only predicate.
- Candidate conjectures restricted initially to universally quantified equations
  `s = t`.
- At most three free variables before universal closure.
- A fixed bounded AST depth, chosen experimentally.

The intended starting theory is a noncommutative semiring: additive commutative
monoid laws, multiplicative monoid laws, left and right distributivity, and zero
annihilation.

For cheap exact classification, finder-side terms may be mapped to the free
noncommutative semiring normal form: a sorted multiset of variable words.
The empty multiset represents zero, the empty word represents one, repeated
words encode natural-number coefficients, and multiplication concatenates
words pairwise. Equality of these normal forms is the equational theory
generated by the semiring axioms above.

Therefore equal normal forms identify theorem candidates, while distinct
normal forms identify negative examples. The normalizer is an untrusted oracle
for search and benchmarking, not a certificate: every claimed theorem must
still be accompanied by a proof accepted through the kernel.

## Trust boundary

The finder is untrusted. It may rank, discard, mutate, or invent candidates by
any heuristic method. Successful discoveries must be represented as proof
objects accepted through the same public checker path as hand-authored input.

The initial semiring bridge emits ordinary Surface v0.1 source for universally
closed equations and submits the resulting module through
`compile_and_check_surface`. The experimental semiring signature and axioms are
themselves explicit Surface postulates. No finder-side normalization, rendering,
or proof generation is trusted for logical validity.

`hott-kernel` must not depend on this crate.

## Version-0 milestones

1. Generate finder-side terms up to a small AST depth.
2. Form candidate equations and remove cheap syntactic junk.
3. Translate selected candidates into the kernel/surface representation.
4. Establish a deliberately weak direct-axiom proof-search baseline and record
   schema attempts plus axiom dependencies for every success.
5. Extend bounded verification with equality symmetry, transitivity, and
   congruence, using breadth-first rewriting under explicit resource bounds.
   Reconstruct every successful derivation as ordinary Surface proof terms and
   require the kernel to accept the composed proof.
6. Measure whether retained discovered lemmas reduce proof-search cost on a
   held-out bounded frontier.
7. Only after the baseline works, introduce best-first search, module selection,
   MCTS, and learned policy/value functions.

The first decisive experimental question is:

> Can automatically discovered lemmas measurably reduce future proof-search cost?
