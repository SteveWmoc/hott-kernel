# Glossary

This glossary fixes project terminology. A term may acquire a more specialized
meaning in a future theory version only through an explicit decision record.

## Algorithmic judgment

A deterministic or decidable procedure used by an implementation, such as
type synthesis, type checking, or conversion checking. Algorithmic judgments
do not define the mathematical theory until they have been related to the
declarative judgments by soundness and completeness results.

## Annotation

Syntax that supplies an expected type to the bidirectional checker. An
annotation guides checking but contributes no new object-theoretic principle.

## Canonicity

A statement that every closed term of a designated data type computes to a
canonical constructor form. Core v0.1 initially targets canonicity for
natural-number terms closed in an environment without a postulate or opaque
definition capable of producing a natural number.

## Core term

A fully explicit term in the small language accepted by the trusted checker.
Surface notation, names for local binders, implicit arguments, tactics, and
metavariables are absent from core terms.

## Declarative judgment

A rule-defined mathematical relation specifying the theory, such as

$$
\Gamma\vdash t:A.
$$

Declarative judgments determine which terms and equalities the kernel is
intended to accept, independently of a particular checking algorithm.

## Definitional or judgmental equality

The metalinguistic equality relation used during type checking and conversion.
In Core v0.1 it is generated by the specified beta-delta-iota computations and
their typed compatible closure. It is not a type, has no inhabitants, and
cannot be assumed within the object theory.

## Declaration dependency

A reference from one checked global declaration to an earlier declaration.
Foundation manifests include the transitive rules, extensions, and postulates
of declaration dependencies.

## Extension

An optional, versioned package that changes or enlarges the accepted theory by
adding formation, introduction, elimination, or computation rules. Examples
may eventually include a higher inductive circle or cubical composition.

An opaque constant named “univalence” is a postulate, not an extension. A
cubical mechanism making univalence computational is an extension.

## Foundation manifest

A deterministic report identifying the kernel theory version and the kernel
features, extensions, postulates, and declaration dependencies used by a
checked declaration. A manifest explains dependencies; it does not replace
rechecking the term.

## Generation provenance

Metadata describing how a candidate term was produced—for example manually,
by a tactic, by an external solver, or with AI assistance. Provenance is not an
object-theoretic dependency and does not determine logical validity.

## Identity type

The object-theoretic, proof-relevant type

$$
\mathsf{Id}_A(a,b).
$$

Its inhabitants are paths and may themselves have nontrivial identity types.
The identity type is distinct from judgmental equality.

## Kernel rule

A primitive rule of the selected core theory, such as universe formation,
dependent-product formation, identity introduction, or a computation rule.
Kernel rules are ambient commitments even when a declaration contains no
postulates.

## Normalization

Computation of a term to a normal form. Strong normalization states that every
reduction sequence from a well-typed term terminates; weak normalization states
only that at least one terminating sequence reaches a normal form.

## Opaque definition

A global declaration with a body that the kernel checks but does not unfold
during conversion after the declaration is accepted. Unlike a postulate, an
opaque definition has a checked body.

## Postulate

A global declaration with a checked type and no body. Postulates are explicit
assumptions and appear in foundation manifests. Excluded middle, choice, or
axiomatic univalence would be postulates if introduced this way.

## Primitive type former

Core syntax and rules creating a class of types, together with any primitive
constructors, eliminators, and computation laws. In Core v0.1 these include
universes, dependent functions, dependent pairs, identity types, empty, unit,
and natural numbers.

## Proof relevance

The absence of a rule identifying arbitrary inhabitants merely because they
inhabit the same proposition-like type. In a proof-relevant theory, identity
proofs may carry data used by later constructions and higher identities.

## Surface elaborator

An untrusted program translating convenient user syntax into fully explicit
core terms. Its output must be checked by the kernel.

## Transparent definition

A checked global definition whose body may unfold during judgmental equality
and normalization.

## Trusted computing base

The components whose correctness is required for a successful check to imply
the claimed judgment. The project seeks to keep this boundary small and to
reduce common-mode failures through an independently implemented checker.
